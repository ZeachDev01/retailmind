# Browser persistence and service-worker research (ticket: Browser persistence and service-worker research)

Context: child of map "Offline-tolerant cashier and inventory spec". Survey only — no queue semantics decided here (owned by sale-queue and inventory-queue tickets).

## How it behaves today (working directory only)

- `src/frontend/components/cashier/pos.php:29-54` — checkout is a synchronous form POST (`cart` JSON + payment/discount fields) → `SalesWorkflowService::checkout()` → redirect to `components/invoice/sales.php`. `csrf_verify()`, open-shift gate (`CashierShiftService::getOpenShift`, pos.php:11-12,139). JS `validateCheckout()` + `submitConfirmedCheckout()` just does `checkoutForm.submit()` (pos.php:970-981). No idempotency key, no offline fallback; network drop = failed POST, cart stays in memory.
- `src/frontend/components/cashier/pos.php:56-94,392-398` — quick-add grid is server-rendered (LIMIT 120, `ORDER BY quantity_sold DESC`), embedded as `quickProducts` JSON + in-memory `productLookup`. Non-grid scans go live to `barcode.php?action=search` via `fetchProductByCode()` (pos.php:665-710). Lookup failure = "Check the network or login session" error, cart add blocked.
- `src/frontend/components/barcodeScanner/apiScanner/products.php:1-60` — GET `q/code/id/category`, auth-gated (`require_role`), JOINs `inventory` + `product_batches` sellable-qty subquery; cashier scope filters `status='active'`, in-stock, non-expired. Limit capped 1–30. Pure network, no cache headers or offline path.
- `src/frontend/components/cashier/findProduct.php:120-158` — debounced (250 ms) `fetch(products.php?q=…&limit=20)` and `?category=…&limit=20`; category list server-rendered (LIMIT 12, findProduct.php:7). Offline = "Unable to load products." No local search index.
- `src/frontend/components/barcodeScanner/sw.js:1-81` — scanner-only worker (`barcode-scanner-v2`): pre-caches `./`, `index.html`, `manifest.json`, html5-qrcode CDN; `fetch` handler explicitly bypasses `/barcodeScanner/apiScanner/` and `/api/` (sw.js:42-44) and all non-GET. POS page, POSTs, and lookups are network-only. No POS registration observed in `pos.php` / `findProduct.php`.
- Browser persistence today: `persistCart()` → `sessionStorage pos_cart` (pos.php:1066-1070), restored on reload (pos.php:1074-1081) but lost on browser/tab-close restart; `persistHeldSales()` is an empty stub (pos.php:1072). Held sales are server-side via `apiScanner/held_sales.php` (`hold/resume/cancel`, pos.php:983-1025) — unavailable offline.
- `src/backend/app/Services/SalesWorkflowService.php:20-54` — `checkout()` sanitizes to `{product_id, qty}`, asserts fiscal periods open, opens transaction, `SELECT … FOR UPDATE` product/shift/batch locks, FEFO batch plan (`buildFefoBatchPlan`), guarded `UPDATE inventory … WHERE quantity_on_hand >= ?`, inserts `sales` / `sale_items` / `sale_item_batches` / `stock_movements ('sale')`. Live dependencies that break offline: open-shift lookup (149-169), supervisor `password_verify` for >10% discount (274-291), `promotions … WHERE NOW()` auto-discount (224-272), `sales.receipt` numbering is auto-increment/`lastInsertId` (313-346).
- `src/backend/app/Services/InventoryCountService.php:21-91` + `inventory_counts.php:41-80` — `recordCount()` is a POST → insert `pending` count (no stock change; approval mutates later in `approveCount()` with system-qty equality guard). Requires `product_id`, `physical_quantity`, `discrepancy_reason`; fiscal-period guard; admin view is read-only, mutate gated by `MUTATE_INVENTORY`. Same offline blockers: auth session, CSRF, live `quantity_on_hand` read.

## Recommendation inputs (for queue-ticket drivers, not decisions)

- IndexedDB queue shape: one object store per payload type (`outbox_sales`, `outbox_counts`) with `{client_uuid, created_at, cashier_id, shift_id, payload, idempotency_key: client_uuid, status: queued/sending/acked/conflict, attempts, last_error}`. `client_uuid` (crypto.randomUUID, persisted in queue record, echoed in POST body) is the replay key — server dedupes on it (needs new nullable unique col; sales/counts tables have none today). localStorage/sessionStorage is insufficient (5 MB sync, no indexing, sessionStorage dies on restart).
- Catalog snapshot scope/freshness: reuse the existing quick-add scope — top-120 active products by `quantity_sold` with `{product_id, sku, barcode, case_barcode, name, unit_price, quantity_on_hand, reorder_level, safety_stock, next_expiration_date}` — cached in IndexedDB (`catalog_snapshot` + `snapshot_meta{captured_at}`), refreshed on each successful online load of `pos.php` / `products.php`. Freeze displayed price at snapshot time with a "prices/stock as of HH:MM" banner; block adds beyond snapshot `quantity_on_hand` with low-stock warning (mirrors `addToCart` guard, pos.php:727-734); full-catalog search stays online-only.
- POST replay with idempotency: on reconnect, FIFO replay with `Idempotency-Key: client_uuid` header + body field; server inserts keyed on unique `client_uuid` and returns existing `sale_id`/`count_id` on duplicate. Replays must re-run server-side guards (shift open, fiscal period, supervisor/discount re-validation, FEFO/stock check) — conflicts surface as server-wins + manual review per standing map decision. No client-side receipt numbering; receipt assigned at ack.
- What stays server-rendered vs cached: cache app shell + static CSS/JS + scanner lib + last catalog snapshot via a POS-scoped worker (`pos-sw.js`, cache-first for GET shell/snapshot, network-first for lookups with snapshot fallback). Stay server-rendered/network-only: checkout POST, held-sale hold/resume, supervisor auth, promotions evaluation, inventory approve/reject, audit (`log_activity`), shift open/close, login/password flows.
