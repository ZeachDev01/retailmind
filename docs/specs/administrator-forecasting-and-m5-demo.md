# Administrator forecasting and M5 walkthrough

Published as [issue #499](https://github.com/ZeachDev01/retailmind/issues/499), labeled `ready-for-agent`.

## Problem Statement

The local Administrator can review and approve a Store candidate, but must ask a Super Administrator to import older sales, request training, adjust the automatic training schedule or candidate error limits, and open Forecast Analytics. A new Store may also need to demonstrate working data import, Python training, and evaluation before it has usable forecasts for purchasing. On the current Windows checkout, no RetailMind ML Scheduler was registered, and the installer skipped registration because its forecasting runner script was absent.

## Solution

Give the local Administrator a complete Store forecasting workflow through sales history import, Data Readiness, training, Forecast Analytics, and Model Review. Show the last scheduler check and job status. Keep explicit model approval and the existing quality and observation gates. Prepare one isolated M5 walkthrough with four role accounts, preloaded historical data, a live import preview and Python training request, and a previous completed run for comparison while live training runs.

## User Stories

1. As an Administrator, I want to import daily sales totals by CSV, so that I can use older Store records for training.
2. As an Administrator, I want to preview accepted, skipped, and invalid data before saving, so that I can correct import problems.
3. As an Administrator, I want POS sales to take precedence for the same Product and date, so that training uses the Store's actual records without duplication.
4. As an Administrator, I want Data Readiness after import, so that I can see which Products can be trained and why others are blocked.
5. As an Administrator, I want to request training explicitly when eligible, so that I can run it before the next schedule.
6. As an Administrator, I want to see queued, running, completed, and failed jobs and the latest scheduler check, so that I can distinguish waiting for data or work from a worker failure.
7. As an Administrator, I want to edit the weekly training day and time in Asia/Manila, so that retraining can fit Store hours.
8. As an Administrator, I want to edit the maximum prediction error for 7, 14, and 28 days, so that I can set the standard for candidate review.
9. As an Administrator, I want to see training run history and a diagnostic reference when a job fails, so that I can understand what happened.
10. As an Administrator, I want to open Forecast Analytics for a completed candidate before approval, so that I can understand its performance even when it fails qualification.
11. As an Administrator, I want to compare predicted and actual sales on held-out historical dates, so that I can show what the training produced.
12. As an Administrator, I want explicit Model Review and approval after the required checks, so that I control when an eligible model begins influencing Store operations.
13. As a Super Administrator, I want continued technical access and audit attribution for changes, so that I can support the Store and trace its decisions.
14. As an Inventory Manager, I want recommendations to use an approved model where usable and stock rules otherwise, so that I can continue working while a candidate is tested.
15. As a presenter, I want four separate signed-in role sessions in one Demo environment, so that I can switch roles without interrupting the walkthrough.
16. As a presenter, I want preloaded M5 history and a live import preview, so that I can show the data path without reimporting the entire dataset in front of the panel.
17. As a presenter, I want a real Admin training job with a visible job ID and a previously completed run, so that I can continue the walkthrough while the live job runs and identify the evidence correctly.
18. As a Cashier, I want to sell an item received by the Inventory Manager and show its receipt, so that the panel can see live stock and POS functionality in the same Demo.
19. As a Store operator, I want Demo activity confined to isolated data and model artifacts, so that the walkthrough cannot affect the live Store.

## Implementation Decisions

- Extend the local Administrator's permissions for sales history import, model retraining, weekly retraining schedule, candidate error limits, and Forecast Analytics. Enforce the permissions at the request boundary and audit the acting account. Keep the Super Administrator's existing access. The permission to edit the weekly training schedule grants no additional control over the daily forecast schedule.
- Reuse the existing CSV validation, preview and confirm workflow. Store daily totals as forecasting evidence. Preserve existing POS precedence and protection against duplicate imports. After confirmation, surface Data Readiness. Training run history is generated by the system.
- Reuse Store Training Eligibility and the existing job queue. Block manual training if no Product qualifies and prevent overlapping training requests. Run the existing Python worker and report the real job state. Make the supported Windows installer capable of registering and launching the forecasting scheduler independently of browser activity.
- Distinguish a recent successful scheduler check with no work, an unavailable or stale scheduler, a queued job, a running job, a failed job, and a completed job. Show candidate qualification independently of job completion.
- Save schedule and quality settings with the existing validation. Saving settings does not start a job or approve a model. Keep the repeat-last-week baseline comparison, chronological evaluation, required Store observation, and explicit local approval. A candidate does not replace an existing approved model before activation.
- Make completed candidate evidence visible to the Administrator in Forecast Analytics. Label historical actual-versus-predicted charts with their data source and dates. Keep historical evaluation distinct from current Store performance and prospective observation.
- Use a single isolated Demo database, model storage, and session setup. Preload the pinned M5 sample via the existing adapter, retain original dates, and use the import preview to demonstrate validation. Run training from the local Administrator role. Keep M5 outputs unavailable for operational guidance, including if candidate checks pass during the walkthrough.
- Show stock-rule replenishment, then record Demo receiving and POS checkout against the same demo item. Demo cashier transactions and inventory movements are created by the role actions. The M5 import supplies forecasting data only.

## Testing Decisions

- Verify behavior through the existing signed-in browser and HTTP workflows. Check both permitted local Administrator actions and denied direct requests from unauthorized roles. Prefer assertions on user-visible results and persisted effects.
- Reuse forecast import and browser workflow coverage for preview, confirmation, validation, POS precedence, readiness, request training, Analytics, and role boundaries. Reuse scheduler and Store forecasting operational tests for queued work, idle and unavailable states, activation gates, and stock-rule fallback.
- Rehearse on Windows using the actual scheduler and Python worker. Check the scheduler task, recent check, request ID, job transitions, and completed training evidence. An initialized Python process or a successful database connection alone is insufficient.
- Reuse the existing M5 browser walkthrough checks for original dates, historical comparisons, blocked operational generation, and stock-rule quantities. Rehearse all four accounts from one baseline and verify the receiving and sale affect only Demo records. Identify the prior completed run separately from the live one.

## Out of Scope

- New forecasting algorithms, changes to Store Training Eligibility, automated activation, or using M5 evidence to clear Store observation and approval.
- Changes to production stock, POS history, operating schedule, or approved models as part of the M5 rehearsal.
- Changing Inventory Manager or Cashier permissions, creating purchase orders, or relaxing quality checks to make the Demo qualify.

## Further Notes

This is a targeted extension of ADR 0022. Routine Store forecasting operations move to the local Administrator, while the activation safeguards and ADR 0023 readiness and lease recovery rules still apply. The previously verified 50-Product M5 run took about four minutes and produced a completed job with failed candidate quality checks. Both outcomes are expected demonstration states.
